# Proposed policies and open decisions

These are preview design proposals, not approved production policies. The implementation README must describe actual behavior and any deviations.

| Topic                | Proposed preview behavior                                                                                                                         | Decision still needed                                                                              |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Frontend framework   | React 19, Vite 7 and strict TypeScript, selected by the user.                                                                                     | Production deployment target.                                                                      |
| Backend and database | No backend or database integration in this phase.                                                                                                 | Technology, hosting, security and operational ownership.                                           |
| Authentication       | Explicit preview identities; no real passwords or account creation.                                                                               | Identity provider, registration, recovery, session policy and verified faculty access.             |
| Meeting duration     | Exactly 30 minutes.                                                                                                                               | No shorter meeting type or buffer setting is proposed.                                             |
| Approval             | Manual approval is the initial proposal; automatic mode is demonstrable. Mode changes affect new requests only.                                   | Confirm production default and who may change it.                                                  |
| Pending holds        | Configurable; a preview may demonstrate nonholding requests, with availability rechecked on acceptance.                                           | Whether pending requests reserve time, hold duration and fairness.                                 |
| Request expiry       | No automatic expiry is implemented. A nullable expiry field is proposed for the future contract, pending lifecycle approval.                      | Duration, reminders, expiry state and student messaging.                                           |
| Availability edits   | Review affected confirmed meetings. Preserve them as exceptions on explicit save, or return without saving.                                       | Final professor-approved conflict policy.                                                          |
| Date overrides       | Date or inclusive date range replaces weekly hours; empty hours means unavailable. Reject overlapping override ranges to avoid hidden precedence. | Whether more complex precedence is needed.                                                         |
| Booking limits       | Notice, booking window and optional daily cap are configurable preview settings.                                                                  | Production values and whether limits include pending requests.                                     |
| Rescheduling         | A proposal leaves the original confirmed appointment reserved until agreement and revalidation.                                                   | Acceptance deadlines, hold policy for proposed slots, notification rules and cancellation cutoffs. |
| Time zones           | Store UTC instants and IANA zones using date-fns-tz. Suppress both nonexistent and repeated local times; display in the viewer's zone.            | Whether production should expose both repeated times with their UTC offsets.                       |
| Integration state    | Booking confirmation is independent of Zoom readiness. Connections remain not connected in the preview.                                           | OAuth scopes, token storage, calendar conflict sources, retry policy and provider outage handling. |
| Reviews              | Ratings and review counts are explicitly illustrative.                                                                                            | Eligibility, moderation, attribution and publication rules.                                        |
| Admin review         | Local faculty-access and booking-support actions only.                                                                                            | Verification evidence, authorization, audit trails and escalation procedures.                      |
| Data persistence     | Optional versioned, resettable local preview storage containing example data only.                                                                | Server retention, privacy requirements and migration policy.                                       |

Production concurrency, authorization and provider credentials cannot be enforced by this frontend preview. Keep those guarantees in the backend contracts rather than presenting local validation as production protection.
